## 1. Spring Container

클래스(Bean)의 생성 → 주입 → 활용 → 소멸 전 과정을 관리하는 핵심 공간

**Container의 Bean 생명주기**
```
클래스 등록 → 객체 생성 → 의존성 주입(DI) → 활용 → 소멸
```

**Container 계층 구조**

```
BeanFactory                       ← DI / Core 기능만 제공 (가장 기본)
    │
ApplicationContext                ← DI / Core / AOP 제공
    │
    ├── AnnotationConfigApplicationContext   ← 순수 Java 코드 기반 설정
    │                                           Spring Boot의 기반
    │
WebApplicationContext             ← DI / Core / AOP / MVC 모두 제공
                                     웹 애플리케이션에서 사용
```

**DL vs DI**

| 구분 | 설명 | 방법 |
|------|------|------|
| DL (Dependency Lookup) | 개발자가 직접 Bean을 찾아서 사용 | `getBean("클래스명")` |
| DI (Dependency Injection) | Container가 자동으로 값을 주입 | 어노테이션 / XML |

> Spring Boot는 `AnnotationConfigApplicationContext` 기반으로 동작하며,  
> XML 설정 없이 어노테이션만으로 Bean을 관리한다.

## 2. DI (Dependency Injection)

객체 생성에 필요한 값을 외부(Container)에서 주입하는 방식.  
직접 `new`로 객체를 생성하지 않고 Container가 대신 생성·주입해준다.

### 1) DI 주입 방식

| 방식 | 설명 | 주요 용도 |
|------|------|---------|
| Setter DI | `setXxx()` 메서드를 통해 값 주입 | 일반 변수값 주입 |
| Constructor DI | 생성자를 통해 객체 단위로 주입 | 객체 의존성 주입 (권장) |
| Method DI | 특정 메서드를 통해 주입 | 초기화 / 소멸 시 처리 |

### 2) 객체 생명주기 메서드

```
객체 생성 → init-method 실행    (예: DB 드라이버 등록, 커넥션 초기화)
           ...활용...
객체 소멸 → destroy-method 실행 (예: Oracle 연결 종료, 자원 반납)
```

### 3) 설정 방법

- **XML 방식** : `applicationContext.xml`에 `<bean>` 태그로 직접 등록 (현재는 거의 사용 안 함)
- **어노테이션 방식** : `@Component`, `@Autowired` 등으로 자동 등록·주입 (현재 표준)

## 3. AOP (Aspect Oriented Programming)

모든 메서드에서 반복적으로 호출되는 **공통 로직을 한 곳에 모아 자동화**하는 기술  
(예: 로깅, 트랜잭션, 보안 체크 등)

### 1) 핵심 개념

| 용어 | 설명 |
|------|------|
| Advice | 공통으로 실행할 로직 (언제 실행할지 규칙 포함) |
| JoinPoint | Advice가 적용되는 시점 |
| PointCut | Advice를 적용할 메서드 범위 지정 |
| Weaving | PointCut으로 선택된 메서드에 Advice를 결합하는 과정 |

### 2) JoinPoint 시점 종류

```java
public String display() {
    // ← BEFORE        : 메서드 실행 전
    try {
        // ← AROUND(전) : try 블록 진입 직후
        
        // 실제 메서드 로직
        
        // ← AROUND(후) : 로직 실행 직후
        
    } catch (Exception e) {
        // ← AFTER_THROWING : 예외 발생 시
    } finally {
        // ← AFTER         : 예외 여부 관계없이 항상 실행
    }
    return 값; // ← AFTER_RETURNING : 정상 반환 시
}
```

### 3) PointCut 표현식

```
pointcut("* com.sist.main.MainClass.*(..)")
          ↑         ↑                ↑  ↑
        return    패키지.클래스      모든 메서드  매개변수 무관
```

- `*` : 모든 return 타입
- `*(..)` : 모든 메서드, 모든 매개변수

> **Transaction도 AOP로 구현됨** → 모든 서비스 메서드에 공통으로 적용되어야 하는 커밋/롤백 처리를 AOP로 자동화한 것

## 4. Spring Framework 전체 구성

Spring은 필요한 기능을 모듈 단위로 조합해서 사용하는 구조다.

| 모듈 | 설명 |
|------|------|
| **Core / DI** | Bean 관리, 의존성 주입 → Spring의 기반 |
| **AOP** | 공통 모듈 자동화 (로깅, 트랜잭션 등) |
| **MVC** | DispatcherServlet 기반 웹 요청 처리 |
| **ORM** | MyBatis / JPA를 통한 DB 연동 |
| **Transaction** | AOP 기반으로 커밋/롤백 자동 처리 |
| **Security** | 인증(로그인) / 인가(권한) 처리 |
| **WebSocket / STOMP** | 실시간 알림, 상담, 그룹 채팅 |

**현재 트렌드**
- XML 설정 → 어노테이션 방식으로 전환 (XML 사용 지양)
- JSP → HTML + Thymeleaf 또는 Vue / React로 전환

### 배운 점
- `BeanFactory` → `ApplicationContext` → `WebApplicationContext` 순서로 기능이 확장되며, Spring Boot는 `AnnotationConfigApplicationContext`를 기반으로 이 과정을 자동화한 것임을 이해함
- DI는 `new` 로 직접 객체를 만들지 않고 Container가 대신 생성·주입해줌으로써 클래스 간 결합도를 낮추는 것이 핵심 목적임을 이해함
- AOP는 Transaction처럼 모든 메서드에 반복되는 공통 처리를 자동화하는 것이며, Spring의 Transaction 기능 자체가 AOP로 구현되어 있다는 점이 인상적이었음
