## 1. GitHub Actions 개요

GitHub에서 제공하는 CI/CD 자동화 도구로, 코드를 push하면 빌드·테스트·배포까지 자동으로 실행된다.

- **CI (Continuous Integration)** : 코드 변경 시 자동으로 빌드 및 테스트
- **CD (Continuous Deployment)** : 빌드 결과물을 자동으로 서버에 배포

**기본 구성 요소**

| 구성 요소 | 설명 |
|---------|------|
| `workflow` | 자동화 작업 전체 단위. `.github/workflows/` 폴더의 yml 파일로 정의 |
| `event` | workflow를 실행시키는 트리거 (push, pull_request 등) |
| `job` | workflow 내 실행 단위. 여러 step으로 구성 |
| `step` | job 안에서 순차적으로 실행되는 개별 명령 |
| `runner` | job이 실행되는 서버 환경 (GitHub 제공 또는 self-hosted) |

---

## 2. Self-hosted Runner 설정

GitHub에서 제공하는 클라우드 Runner 대신 **직접 Ubuntu 서버를 Runner로 등록**해서 사용했다.

- GitHub Repository → Settings → Actions → Runners → New self-hosted runner에서 등록
- 설치 후 Ubuntu에서 아래 명령으로 Runner를 실행해 GitHub Actions의 신호를 대기

```bash
cd actions-runner/
./run.sh
```

Runner가 실행 중인 상태에서 push가 발생하면 deploy.yml의 job이 해당 Ubuntu 서버에서 실행된다.

## 3. deploy.yml 작성

GitHub Repository의 `.github/workflows/deploy.yml`에 작성한 배포 자동화 스크립트

```yaml
name: Java CI with Maven

# master 브랜치에 push될 때 실행
on:
  push:
    branches: [ "master" ]

jobs:
  deploy:
    runs-on: self-hosted        # 직접 등록한 Ubuntu 서버에서 실행
    defaults:
      run:
        working-directory: .    # 기본 작업 디렉토리

    steps:
      # 1. 코드 체크아웃
      - name: Checkout
        uses: actions/checkout@v4

      # 2. Maven 빌드 (테스트 생략)
      - name: Maven Build
        run: mvn clean package -DskipTests

      # 3. 기존 Tomcat 종료
      - name: Stop Tomcat
        run: |
          /home/sist/apache-tomcat-9.0.120/bin/shutdown.sh || true
          sleep 3

      # 4. 기존 배포 파일 삭제
      - name: Remove Old War
        run: |
          rm -rf /home/sist/apache-tomcat-9.0.120/webapps/SpringLastProject.war
          rm -rf /home/sist/apache-tomcat-9.0.120/webapps/SpringLastProject

      # 5. 새 War 파일 복사
      - name: Deploy War
        run: |
          cp target/*.war /home/sist/apache-tomcat-9.0.120/webapps/SpringLastProject.war

      # 6. Tomcat 시작
      - name: Tomcat Start
        env:
          RUNNER_TRACKING_ID: ""    # GitHub Actions 종료 후에도 Tomcat 유지
        run: |
          nohup /home/sist/apache-tomcat-9.0.120/bin/startup.sh
          sleep 5
          ps -ef | grep tomcat
```

**각 step 설명**

| step | 명령 | 역할 |
|------|------|------|
| Checkout | `actions/checkout@v4` | 현재 Repository 코드를 Runner 서버로 내려받음 |
| Maven Build | `mvn clean package -DskipTests` | 프로젝트 빌드 후 `.war` 파일 생성, 테스트 생략 |
| Stop Tomcat | `shutdown.sh \|\| true` | 기존 Tomcat 종료. 이미 꺼진 경우에도 오류 없이 진행 |
| Remove Old War | `rm -rf` | 이전 배포 파일 삭제 (구버전 잔존 방지) |
| Deploy War | `cp target/*.war` | 새로 빌드된 `.war` 파일을 Tomcat webapps에 복사 |
| Tomcat Start | `nohup startup.sh` | Tomcat 재시작 후 프로세스 확인 |

## 4. 배포 흐름

```
코드 작성 → git push (master)
                │
                ▼
        GitHub Actions 트리거
                │
                ▼
        Self-hosted Runner (Ubuntu) 에서 job 실행
                │
          ┌─────▼─────┐
          │  Checkout  │  코드 다운로드
          └─────┬─────┘
          ┌─────▼─────┐
          │Maven Build │  .war 파일 생성
          └─────┬─────┘
          ┌─────▼─────┐
          │Stop Tomcat │  기존 서버 종료
          └─────┬─────┘
          ┌─────▼─────┐
          │ Remove War │  구버전 삭제
          └─────┬─────┘
          ┌─────▼─────┐
          │Deploy War  │  새 버전 복사
          └─────┬─────┘
          ┌─────▼─────┐
          │Start Tomcat│  서버 재시작
          └─────┬─────┘
                │
                ▼
        배포 완료 → 브라우저에서 확인
```

push 한 번으로 빌드부터 서버 재시작까지 전 과정이 자동으로 처리된다.

## 5. 트러블슈팅 - Tomcat 자동 종료 문제

### 문제 상황
deploy.yml 실행이 완료되자마자 Tomcat 서버도 함께 종료되는 문제 발생

### 원인
GitHub Actions Runner는 job이 완료되면 해당 job에서 생성된 **모든 자식 프로세스를 추적해서 함께 종료**시킨다.  
Tomcat이 Runner의 자식 프로세스로 실행되었기 때문에, Actions job 종료와 동시에 Tomcat도 같이 종료된 것이다.

### 해결
Tomcat Start step에 `RUNNER_TRACKING_ID: ""` 환경변수를 추가

```yaml
- name: Tomcat Start
  env:
    RUNNER_TRACKING_ID: ""    # 이 값을 비워두면 Runner가 해당 프로세스를 추적하지 않음
  run: |
    nohup /home/sist/apache-tomcat-9.0.120/bin/startup.sh
```

`RUNNER_TRACKING_ID`를 빈 값으로 설정하면 Runner가 Tomcat 프로세스를 추적 대상에서 제외해,  
Actions job이 종료된 이후에도 Tomcat이 독립적으로 계속 실행된다.

## 💡 Note

### 오늘 한 일
- GitHub Actions에서 Java Maven 템플릿으로 deploy.yml 작성
- Ubuntu에 Self-hosted Runner 등록 및 실행
- master 브랜치 push 시 자동 빌드 → Tomcat 재배포 파이프라인 구성
- Tomcat 자동 종료 문제 발생 및 `RUNNER_TRACKING_ID` 환경변수로 해결

### 배운 점
- GitHub Actions를 통해 push 한 번으로 빌드·배포가 자동화되면서, 기존에 직접 서버에 접속해 파일을 복사하고 Tomcat을 재시작하던 수동 과정이 완전히 대체됨을 경험함
- Self-hosted Runner를 사용하면 GitHub 클라우드 환경이 아닌 **직접 운영 중인 서버에서 배포**가 가능하다는 점을 이해함
- Runner가 job 종료 시 자식 프로세스를 함께 종료하는 동작 방식을 이해하고, `RUNNER_TRACKING_ID` 환경변수로 추적을 해제해 해결하는 과정에서 CI/CD 환경의 프로세스 관리 방식을 이해함
