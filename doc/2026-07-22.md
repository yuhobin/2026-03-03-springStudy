## 1. 어노테이션 개요

Spring 설정 방식은 **어노테이션(80%) + XML(20%)** 비율로 사용된다.

어노테이션의 주요 역할은 **클래스를 Container에 등록(메모리 할당)** 하고, 각 클래스의 역할을 구분하는 것이다.  
`<context:component-scan>` 설정을 통해 지정한 패키지를 탐색하고 어노테이션이 붙은 클래스를 자동으로 Bean으로 등록한다.

## 2. 클래스 구분 어노테이션

### 1) 계층별 구분

| 어노테이션 | 계층 | 역할 |
|-----------|------|------|
| `@Controller` | Presentation | View(JSP, Thymeleaf) 반환. 화면 이동 담당 |
| `@RestController` | Presentation | JSON / XML 데이터 반환. Rest API 전용 |
| `@Service` | Business | 비즈니스 로직 처리 계층 |
| `@Repository` | Data Access | DB 연동 담당 (DAO 역할) |
| `@Component` | 공통 | 위 계층에 속하지 않는 일반 클래스에 사용. 나머지 어노테이션의 상위 개념 |
| `@Configuration` | 설정 | XML 설정을 Java 코드로 대체할 때 사용 |

### 2) @Controller vs @RestController

| 구분 | @Controller | @RestController |
|------|------------|----------------|
| 반환 타입 | View 이름 (String) | 데이터 (JSON / XML) |
| 주요 용도 | JSP / Thymeleaf 화면 이동 | Vue, React 등과의 Rest API 연동 |
| 데이터 변환 | 직접 처리 | JSON 자동 변환 |

### 3) 전체 요청 처리 흐름

```
User → DispatcherServlet → @Controller / @RestController
                                  │
                               @Service
                                  │
                             @Repository
                                  │
                                 DB
                                  │
                    (역순으로 데이터 반환)
                                  │
                            JSP / HTML
```

### 4) @ControllerAdvice / @RestControllerAdvice

공통 예외 처리를 위한 어노테이션으로, 모든 Controller에서 발생하는 예외를 **한 곳에서 통합 처리**한다.

- `@ControllerAdvice` : View를 반환하는 Controller의 예외 처리
- `@RestControllerAdvice` : Rest API Controller의 예외 처리 (JSON 반환)

> AOP의 `@AfterThrowing`과 같은 개념을 Controller 예외에 특화해서 적용한 것

## 3. Spring Container 종류

| Container | 설명 | 사용 환경 |
|-----------|------|---------|
| `ApplicationContext` | 기본 DI / AOP 컨테이너 | 일반 애플리케이션 |
| `WebApplicationContext` | MVC 포함 웹 전용 컨테이너 | 웹 애플리케이션 |
| `AnnotationConfigApplicationContext` | 어노테이션 기반 순수 Java 설정 컨테이너 | Spring Boot 기반 |

## 4. Spring의 활용 범위

Spring은 웹 전용 프레임워크가 아닌 **애플리케이션 전반에 사용 가능한 프레임워크**다.

- 클래스 수가 많고 복잡한 구조의 애플리케이션(게임 서버 등)에서도 DI / AOP로 클래스 관계를 효율적으로 관리 가능
- Java뿐 아니라 **Kotlin**과도 완전 호환
  - Kotlin은 JVM 기반으로 Java와 동일하게 동작
  - Spring 어노테이션을 그대로 사용 가능
  - `var`(변수) / `val`(상수) 문법 차이 외에 Spring 활용 방식은 동일

### 배운 점
- `@Component`가 모든 계층 어노테이션(`@Controller`, `@Service`, `@Repository`)의 상위 개념이며, 나머지는 역할을 명시적으로 표현하기 위해 세분화된 것임을 이해함
- `@ControllerAdvice`가 AOP의 예외 처리 시점(`@AfterThrowing`)을 Controller에 특화해서 적용한 것이라는 점에서 앞서 학습한 AOP 개념과 자연스럽게 연결됨
- Spring이 웹에만 국한되지 않고 복잡한 클래스 구조를 가진 모든 애플리케이션에 활용 가능한 범용 프레임워크라는 것을 이해함
