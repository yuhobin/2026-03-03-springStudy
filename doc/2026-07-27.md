## 1. REST API와 HTTP 매핑 어노테이션

REST API는 HTTP 메서드로 CRUD를 표현하는 설계 방식이다.

| 어노테이션 | CRUD | 주요 사용 상황 |
|-----------|------|-------------|
| `@GetMapping` | SELECT (조회) | 데이터 조회, 화면 요청 |
| `@PostMapping` | INSERT (등록) | 데이터 저장 |
| `@PutMapping` | UPDATE (수정) | 데이터 전체 수정 |
| `@DeleteMapping` | DELETE (삭제) | 데이터 삭제 |
| `@RequestMapping` | 전체 통합 | GET/POST/PUT/DELETE 모두 처리 |

**웹에서의 실질적 사용 범위**
- 일반 웹 페이지(form 기반) : `@GetMapping` / `@PostMapping` 위주로 사용
- REST API(Vue, React 연동) : `@PutMapping` / `@DeleteMapping` 까지 모두 활용

**Spring 버전 변화**
- Spring 6부터 `@RequestMapping`을 Controller 메서드 레벨에서 단독 사용하는 방식이 점차 줄어드는 추세
- 각 HTTP 메서드에 맞는 전용 어노테이션 사용이 권장됨

## 2. DispatcherServlet 처리 흐름

Spring MVC의 핵심 구성 요소로, 모든 요청의 진입점 역할을 한다

```
클라이언트 요청
      │
      ▼
DispatcherServlet         ← 요청을 받아 전체 흐름을 제어하는 Front Controller
      │
      ▼
HandlerMapping            ← @RequestMapping을 탐색해 처리할 Controller 메서드를 찾음
      │
      ▼
Controller (실행)          ← 비즈니스 로직 처리, Model에 데이터 담기
      │
      ▼
ViewResolver              ← Controller가 반환한 View 이름으로 실제 JSP 경로를 결정
      │
      ▼
JSP (View 렌더링)          ← 최종 화면 생성 후 클라이언트에 응답
```

**각 구성 요소 역할 요약**

| 구성 요소 | 역할 |
|---------|------|
| `DispatcherServlet` | 요청 수신 및 전체 흐름 제어 (Front Controller 패턴) |
| `HandlerMapping` | 요청 URL에 맞는 Controller 메서드 탐색 |
| `ViewResolver` | 논리적 View 이름 → 실제 JSP 파일 경로로 변환 |
| `JSP` | 데이터를 바탕으로 최종 화면 렌더링 |

## 3. WebApplicationContext

`DispatcherServlet`과 함께 동작하는 Spring의 IoC 컨테이너

- Spring Bean(Controller, Service, Repository 등)을 생성하고 관리
- `DispatcherServlet`은 요청이 들어오면 `WebApplicationContext`에서 필요한 Bean을 꺼내 사용
- 즉, **DispatcherServlet ↔ WebApplicationContext**가 함께 맞물려 Spring MVC가 동작함

```
DispatcherServlet  ══════  WebApplicationContext
       │                         │
  요청 흐름 제어            Bean 생성 및 관리
                           (Controller, Service,
                            Repository, ViewResolver 등)
```

### 배운 점
- `@PutMapping` / `@DeleteMapping`은 form 태그로는 전송이 불가능하고 Axios나 fetch 같은 JavaScript 통신에서만 사용 가능하다는 것을 이해함 → Vue/React와의 연동이 전제된 어노테이션
- DispatcherServlet이 단순히 요청을 받는 것이 아니라 HandlerMapping → Controller → ViewResolver 전체 흐름을 조율하는 **Front Controller** 역할임을 이해함
- ViewResolver 덕분에 Controller에서 JSP 전체 경로 대신 논리적인 이름만 반환해도 되는 이유를 이해함
